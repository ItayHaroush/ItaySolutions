# External proposal approvals — implemented in Buildix

The Laravel backend lives in Buildix, not in PortfolioReact.

## Endpoints

POST `/api/proposals/prepare` — create client + quote  
POST `/api/proposals/attachment` — upload full itaysolutions PDF as quote attachment  
POST `/api/proposals/approve` — sign + attach signed PDF + regenerate Buildix PDF  
GET/POST `/api/proposals/branding` — logo + business name sync

Production base: https://app.buildix.site/api/proposals/

## PDF attachment (not a link)

The hosted proposal page generates a full print PDF and uploads it to Buildix as
`attachment_path` on the quote — the same field used by manual "load document" in
Buildix UI. When Buildix regenerates the quote PDF, the attachment is appended at
the end of the original quote document.

Flow:
1. Owner creates quote via `/proposals/` → prepare
2. Proposal page auto-uploads draft PDF to `/api/proposals/attachment`
3. Client signs → signed PDF replaces attachment via `/api/proposals/approve`
4. Buildix PDF = original quote + full itaysolutions proposal at the end

Do **not** store a document URL in quote notes — use the attachment API only.

## Deploy on VPS

```bash
cd backend
git pull
php artisan migrate
# restart php-fpm / queue if needed
```

`.env`:
```env
BUILDIX_EXTERNAL_PROPOSAL_NOTIFY_EMAIL=itay@itaysolutions.com
BUILDIX_EXTERNAL_PROPOSAL_ORIGINS=https://www.itaysolutions.com,https://itaysolutions.com
```

## Connect PortfolioReact

`proposals/proposal-backend-config.js`:
```javascript
window.PROPOSAL_ATTACHMENT_URL = "https://app.buildix.site/api/proposals/attachment";
```

The duplicate PHP snippets in this folder are reference-only; Buildix is the source of truth.
